# Audience and Use Research

Status: scoped as an internal technical operating brain, not validated as a commercial product.

## Audience

The supported audience is developers and operators who need to understand, run, extend, debug, or review DeepSeek Harness. The upstream repository documents contributor, operator, plugin-development, Web UI, CLI, Python SDK, and agent-facing entry paths, which establishes distinct information needs inside that audience.

## Recurring Jobs

- Orient quickly in a 234-package TypeScript monorepo plus Python, native, Web, example, and vendored surfaces.
- Trace ownership across Cordis composition, service definitions, providers, consumers, events, durable session state, and client projections.
- Decide where a new feature belongs without modifying the concrete loop unnecessarily.
- Review permissions, sandboxing, approvals, credentials, subprocesses, persistence, and host trust as separate controls.
- Select a verification tier that actually exercises the behavior under review.
- Diagnose lifecycle, cancellation, teardown, concurrency, and built-entrypoint failures.
- Refresh notes when developer-preview changes invalidate names, defaults, events, formats, or release evidence.

## User Value Hypothesis

The brain reduces repeated repository archaeology and prevents evidence inflation. Its durable value is not a generic summary. It is the linked map from a question to the owning package, current contract, counterexample, verification tier, and pinned source locator.

## Boundaries

- No commercial demand, willingness-to-pay, conversion, or market-size claim has been validated.
- No competitor comparison is included because the requested artifact is a grounded operating reference for this repository.
- The repository's GitHub visibility or community links are not treated as proof of paid demand.
- Any future public product positioning needs separate current research and an explicit user decision.
