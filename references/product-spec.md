# DeepSeek Harness Brain Product Spec

## Buyer

Developers and operators who need source-cited guidance for understanding, running, extending, or reviewing DeepSeek Harness.

## Domain

DeepSeek Harness architecture, operations, extension development, security, testing, and debugging

## Core Workflows

- Orient a contributor across profiles, bundles, Cordis plugins, services, events, sessions, agents, tools, and clients
- Trace one model turn from inbox admission through prompt assembly, LLM streaming, tool execution, persistence, and UI projection
- Design a capability extension using Service Definition, Service Provider, and Consumer roles
- Review a tool or plugin for permissions, sandboxing, approval, durable logging, teardown, and replay behavior
- Diagnose lifecycle, cancellation, concurrency, subprocess, persistence, and configuration failures
- Select the smallest meaningful verification tier and distinguish keyless, built, snapshot, browser, and real-API evidence
- Run and configure Web or headless profiles without exposing credentials or weakening permission defaults

## Deliverables

- System architecture map and profile composition guide
- Turn, step, session, prompt, tool, and persistence lifecycle reference
- Capability seam and plugin extension playbooks
- Security and trust-boundary review with verified facts, inferences, and open risks separated
- Testing and release evidence ladder
- Configuration, operations, troubleshooting, and source navigation guides
- Claim ledger, source ledger, glossary, and decision records tied to pinned source locators

## Promise

Turn raw sources and recurring decisions into a persistent, source-cited
operating brain.

## Non-Promises

- No claim that a keyless, static, build, snapshot, browser, or real-API check proves a stronger tier than it actually ran
- No invented package behavior, event semantics, defaults, compatibility promise, vulnerability, benchmark, or release status
- No credentials, tokens, cookies, private settings, or local secret values in brain artifacts
- No instruction to weaken sandbox, approval, host-trust, or credential boundaries merely to make a command pass
- No mutation, publication, deployment, account change, or production action from this advisory brain
- No reliance on archived Agent Notes as current authority when source or current documentation disagrees
